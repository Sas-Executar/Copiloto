# Information Mapping Rules

## Context
Map the statement that best explains what the work is and why it exists.

## Problem
Map the principal gap, blocker, bottleneck, deficiency, or unresolved condition.

## Process
Map what is happening now to move the work forward.

## Progress
Map the next meaningful state change or already achieved advancement; keep it distinct from numeric project progress.

## Steps
Map explicit sequential actions first.

If more than three exist, select the next three execution-relevant steps.

If fewer than three are supported, use `Não identificado no documento`.

## Risk
Map the most material source-supported condition that can compromise delivery, quality, safety, consistency, or schedule.

## Prevention
Map explicit mitigation only; otherwise use `Não identificado no documento`.

## Delivery
Map the final verifiable output, artifact, state, or acceptance condition.

## Now action
Choose in this order:
1. explicitly marked `agora`, `next`, `próxima ação`, or `today`;
2. unblocked task with earliest dependency position;
3. first incomplete action in an explicit sequence.

## Percentages
Use a percentage only when explicitly stated or when numerator and denominator are both explicit and compatible.

Mark calculations as `derived` in provenance.
